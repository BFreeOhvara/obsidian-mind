**The idea (Brayden's own framing, confirmed deliberately — not impersonation):** when Fulfillment calls a client to work a cancellation, the client's phone shows the *agent's* number, not Fulfillment's — the client already knows and trusts that number from the original sales call, so they're more likely to pick up. Fulfillment never claims to *be* the agent on the call — they say they're calling on the agent's behalf (e.g. "Hey, this is Fulfillment calling on behalf of Nate — we spoke with you about getting your old policy cancelled"). This applies regardless of who's actually on either end of the call — Brayden was explicit this isn't about matching the Fulfillment rep's gender/identity to the agent's, it's purely "on behalf of," stated honestly.

**Technical shape once the Twilio account exists (real latitude on exact implementation — Opus's call):**
- Each agent needs their real cell number **verified** as an outbound Caller ID via Twilio's Verified Caller ID flow (Twilio sends a one-time code to that number by call or text; the agent enters it once). Store the verified number + verification status on `profiles` (new columns — migration needed, flag it).
- Default/recommended call shape: Twilio places a two-leg bridged call — rings the Fulfillment rep first (at their own number on file; check whether `profiles` already has one, add it if not), then connects them to the client, with the Caller ID the client sees set to the agent's verified number. This keeps reps using their own phone/device like today's plain `tel:` link, just routed through Twilio instead of dialing directly.
- In `FulfillmentQueue.jsx`'s `WorkView`, replace the current `tel:${p.client_phone}` link with a "Call client" action that triggers this bridged call (new edge function, e.g. `start-agent-caller-id-call`, using the Twilio REST API's Calls resource with the agent's verified number as `callerId`).
- Bake a script guardrail into the UI itself, not just this spec — a visible reminder in the work view, same pattern as `Submissions.jsx`'s existing "Read to the client" hint: something like "You're calling on behalf of {agent name} — never say you are them."

When off, Fulfillment's call falls back to today's plain `tel:` link behavior (Fulfillment's own number shown, no bridging).
